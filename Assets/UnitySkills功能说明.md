# UnitySkills 功能说明

UnitySkills 是一套通过本地 REST 服务自动化 Unity Editor 的工具，可以让 AI 助手查询项目状态，并在获得适当授权后操作场景、脚本、资源和编辑器功能。

## 主要功能

### 项目与编辑器查询

- 获取 Unity 版本、项目名称、项目路径、目标平台和渲染管线。
- 查询编辑器状态、当前选择、标签、层级、编译结果及控制台日志。
- 分析场景结构、项目技术栈、资源信息和潜在问题。

### 场景与 GameObject

- 查询、创建和管理场景中的 GameObject。
- 添加、移除、启用或配置组件。
- 调整对象的父子关系、位置、旋转和缩放。
- 管理相机、灯光、物理、NavMesh、Terrain、UGUI 和 UI Toolkit 等内容。

### 脚本与代码

- 创建、读取、搜索、移动和修改 C# 脚本。
- 获取编译反馈，定位错误与警告。
- 在脚本变更触发编译或域重载后，等待服务恢复并继续验证。
- 可结合架构、可测试性、异步、性能及常用 Unity 插件的设计指南辅助开发。

### 材质、Shader 与渲染

- 查询和修改材质的颜色、纹理、数值、关键字及渲染队列。
- 创建、读取和检查 ShaderLab/HLSL Shader。
- 管理 Shader Graph、URP Renderer Feature、Volume、后处理和 Decal。
- 查询项目当前渲染管线，并给出适配该管线的 Shader 信息。

### 资源与 Prefab

- 查找资源并读取 AssetDatabase 信息。
- 管理导入设置、ScriptableObject、Prefab、Animator、Timeline 等资源。
- 支持 Addressables、YooAsset 和 Unity Package Manager 相关工作流。

### 测试、调试与性能

- 运行和轮询 Unity Test Runner 的 EditMode 或 PlayMode 测试。
- 查询控制台错误、编译状态、内存信息和系统状态。
- 获取 Profiler 快照，辅助分析帧耗时、内存及资源使用情况。
- 检查缺失脚本、断开的引用和其他项目健康问题。

### 批处理与工作流

- 对多个对象优先使用批处理操作，减少重复调用。
- 多步骤任务可先生成聚合计划，检查步骤依赖与风险。
- 支持批量 dry-run；需要时可使用事务模式，在步骤失败后尝试通过 Unity Undo 回滚。
- 资源文件的磁盘写入不一定能被 Unity Undo 完整恢复，因此仍需在执行前确认影响范围。

## 安全机制

### 只读检查

查询类技能会标记为只读，不修改场景或资源。检查安装状态、项目资料、编译结果和控制台日志时，应优先使用只读技能。

### Dry-run

首次调用某项技能前可以使用 dry-run：

1. 校验技能名称与参数。
2. 显示操作类型、风险级别和可能影响。
3. 确认是否会修改场景、资源，或触发编译、域重载及 Play Mode。
4. dry-run 本身不执行实际修改。

### 权限模式

UnitySkills 支持 Approval、Auto 和 Bypass 三种服务端权限模式。当前安装使用 **Auto**：

- 普通可写操作可以直接执行，但仍应先评估影响。
- 批量修改、Prefab Apply、场景级变更和资源覆盖应先明确确认。
- 删除、进入 Play Mode、触发域重载及其他高风险操作可能受到额外限制。

### 高风险确认

权限模式与单次高风险确认互相独立。即使技能已被允许，高风险操作仍可能返回确认令牌；只有在用户确认具体影响后，才应使用该令牌继续执行。

## 常见使用示例

可以用自然语言向 AI 助手提出类似请求：

- “检查当前 Unity 项目的版本和渲染管线，不要修改任何内容。”
- “读取当前场景层级，找出带有 Missing Script 的对象。”
- “先 dry-run，告诉我批量修改这些材质会影响哪些资源。”
- “运行 EditMode 测试，并汇总失败用例，不要自动修改代码。”
- “检查控制台中的编译错误，并解释可能原因。”
- “创建对象或修改场景前，先列出计划和风险，等我确认。”

## 使用注意事项

- 脚本、程序集定义、包和部分资源发生变化时，Unity 可能开始编译或执行 Domain Reload。
- 域重载期间本地服务可能短暂返回连接失败或 `503/504`；通常等待数秒并重新检查 `/health` 即可。
- 修改脚本后应读取 `/compile/status`，确认编译是否成功并检查具体错误。
- 测试技能通常异步执行，需要保存返回的任务 ID 并轮询结果。
- 多对象操作应优先选用批处理技能；多步骤写入应先进行工作流规划和 dry-run。
- Unity 6000.4 及更高版本应优先使用 `entityId` 定位对象；本项目当前为 Unity 2022.3，仍可使用传统实例 ID。
- 在版本控制项目中执行写入操作前，建议确认工作区状态，并只提交预期变更。
